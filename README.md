# Salin

Turns MKV — and most other video containers — into MP4 or MP3, **copying the
streams instead of re-encoding them whenever it can**.

Salin is Filipino for a transfer or a copy, which is exactly what the app does
most of the time. It is a companion to [Bulong](../local-wispr), and shares its
shape: Electron, React, everything local, nothing sent anywhere.

---

## Why this exists

Most GUI converters re-encode unconditionally. Hand them a 4 GB MKV and they
spend twenty minutes rebuilding a video stream that an MP4 could have held
untouched — and the copy that comes out is slightly worse than the one that went
in, because that is what re-encoding does.

An MKV and an MP4 are both *containers*. If the video inside is already H.264 or
HEVC and the audio is already AAC, converting between them is a matter of
rewriting the wrapper: a few seconds, byte-identical picture and sound.

Salin probes every file first, works out whether a copy is possible, and shows
you the answer before you commit:

```
VIDEO      ●───────  H.264  ───────●   COPY
AUDIO      ●───────  AAC    ───────●   COPY
SUBTITLES  ●───────  SubRip → mov_text ───────●   COPY
                                        REMUX · SECONDS
```

Mint means carried across untouched. Cyan means rebuilt, and the line animates
while it is happening. A re-encode is always explained — *"AC-3 audio isn't
something an MP4 can hold, so it becomes AAC"* — rather than just happening.

## What it does

- **MP4 or MP3** from mkv, avi, mov, webm, wmv, flv, ts, m2ts, m4v, mpg, 3gp, ogv, mp4
- **Copies rather than re-encodes** wherever the format allows, and says which
- **Audio track picker** — MKVs routinely carry three languages, and the default
  is whichever one the file itself marks as default, not blindly the first
- **Subtitles** — leave out, carry across as a selectable track (`mov_text`), or
  burn into the picture
- **Batch queue**, one conversion at a time, with live progress, speed, ETA and
  a working Stop button
- **Never overwrites**: output goes next to the source (or a folder you pick),
  and a name collision gets a number rather than eating your file
- Writes to a `.part` sidecar and renames on success, so a crash or a cancel
  can't leave something that looks like a finished video

## What it deliberately doesn't do

No GPU encoding, no trimming or cropping, no preview player, no chapter editing,
no MKV output. It converts files, and that is all.

## Requirements

Salin does not bundle ffmpeg — it uses the one on your system, which keeps the
download small and picks up whatever codecs your install has.

```bash
brew install ffmpeg      # macOS
winget install Gyan.FFmpeg   # Windows
```

The app checks for it on launch and shows the exact command if it is missing.

### A note on burning in subtitles

Rendering *text* subtitles onto the picture needs ffmpeg's `subtitles` filter,
which only exists in builds compiled with **libass**. Homebrew's current ffmpeg
is not one of them.

Salin probes for the filter at startup rather than discovering this ten minutes
into a job: where it is absent, the burn-in option is greyed out for text
subtitles with the reason shown, and new files default to carrying them as a
selectable track instead. Image-based subtitles (PGS, VobSub) are composited
with `overlay` and burn in on any build.

To get libass on macOS, install an ffmpeg built with it — for example
`brew install ffmpeg --HEAD` against a formula that enables it, or a static
build from [evermeet.cx](https://evermeet.cx/ffmpeg/) placed on your `PATH`.

## Development

```bash
npm install
npm run dev        # electron-vite, hot reload
npm test           # vitest — builds real fixtures with ffmpeg
npm run typecheck
npm run app        # → release/mac-arm64/Salin.app
npm run app:win    # → release/Salin-1.0.0-win.zip
```

The tests are not mocked. Every fixture is generated by ffmpeg from lavfi
sources at the start of a run, and the conversions are real: the central claim —
that a copyable MKV is copied, not re-encoded — is checked by comparing the MD5
of the *encoded packets* before and after, which no re-encode could ever match.

### How it is put together

```
src/
  shared/
    types.ts     the vocabulary shared by all three processes
    plan.ts      PURE. MediaInfo + options → decisions, explanations, argv
  main/
    probe.ts     ffprobe → MediaInfo
    convert.ts   spawn ffmpeg, parse -progress, cancel, clean up
    queue.ts     one job at a time
    store.ts     one JSON file per job
    deps.ts      finds ffmpeg on a PATH that Finder didn't provide
    ipc.ts       every handler, in one place
  preload/       a fixed set of named methods, not a generic invoke()
  renderer/      React, Tailwind, hash routing
```

`shared/plan.ts` is the interesting one. It is pure — no ffmpeg, no filesystem,
no Electron — which is what lets the renderer draw the pipeline trace from
exactly the same decisions the main process will run, and lets the whole
copy-versus-encode matrix be tested without touching a file.

Two things in there look stranger than they are, and both are load-bearing:

- **`-tag:v hvc1`** on a copied HEVC stream. Without it the MP4 is tagged
  `hev1`, and QuickTime and iOS refuse to play a file that is otherwise
  perfectly valid.
- **`quoteFilterPath`**. An ffmpeg filtergraph is unescaped *twice*, with
  different rules each time, so a film called `Pulp: it's a [test].mkv` needs
  three separate escapes layered in the right order. Every simpler form of it
  fails on at least one real filename; the tests cover all of them.

## Installing the built app

The macOS build is **ad-hoc signed**, not notarised — there is no paid Apple
Developer account behind it. Gatekeeper will stop the first open on another Mac
with the ordinary unidentified-developer prompt: right-click the app, choose
Open, then Open again.

(Ad-hoc signing matters. With signing skipped entirely, the bundle keeps the
stale linker signature Electron ships with, and macOS refuses it outright as
"damaged", with no way past. An ad-hoc signature is untrusted but *valid*, which
turns a dead end into a prompt.)

The Windows build is an unsigned portable zip; SmartScreen will warn once, and
"More info → Run anyway" gets past it.
